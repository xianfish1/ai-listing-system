# 本地文件夹批量导入商品设计

## 目标

让“从本地创建”具备与 NAS 创建相近的批量能力。用户只需选择一次上级目录，系统便把其中的多个一级商品文件夹分别创建为基础商品，同时继续兼容现有的单商品文件夹导入。

## 目录识别规则

1. 浏览器读取用户选中的整个目录树，并过滤隐藏目录及不支持的文件类型。
2. 如果所选根目录的一级子目录中有两个或更多目录包含受支持素材，则每个这样的一级子目录视为一个独立商品。
3. 如果不满足批量条件，则保持现有行为，把所选根目录整体视为一个商品。
4. 批量模式中，根目录直属素材不创建额外商品，也不会混入子目录商品；界面明确提示这些文件被忽略。
5. 商品目录内部的嵌套结构完整保留，以便继续使用现有素材扫描、SKU 识别、颜色识别和 AI 商品生成规则。

## 用户流程

1. 用户点击“从本地创建”，选择包含多个商品文件夹的上级目录。
2. 页面立即汇总识别出的商品数量、有效文件数量和忽略文件数量。
3. 用户确认后把该批商品加入导入队列；单商品模式不增加额外确认步骤。
4. 队列串行执行：页面显示当前商品、等待中的商品、已完成/失败计数和逐项明细。
5. 上一个目录还没导入完时，用户可以继续选择下一个目录：新目录排在队列末尾，不需要等待。
6. 每个商品完成后刷新商品列表；队列跑空后刷新素材和就绪状态。
7. 等待中的商品可以逐项移除，也可以一次性清空待处理项。

## 导入队列

- 队列的调度单元是**商品目录**，不是“一次选择”：连续选择多个上级目录时，所有商品目录按加入顺序排在同一条队列里串行执行。
- 同一时刻只有一个商品在上传/创建，避免多个大文件夹同时上传造成浏览器、磁盘和 AI 服务压力。
- 队列只活在当前页面：`File` 句柄无法持久化，刷新或关闭页面会丢弃尚未开始的项（队列非空时浏览器会拦一次刷新确认）。
- 队列状态完全在前端维护；后端仍然只看到与单商品导入相同的上传会话和创建接口。

## 实现边界

- 前端负责根据 `webkitRelativePath` 分组、为每个商品创建独立上传会话并上传文件。
- 后端继续复用现有单商品上传会话及创建接口，不新增另一套商品创建逻辑。
- 批量任务按商品串行处理，避免多个大文件夹同时上传造成浏览器、磁盘和 AI 服务压力。
- 串行调度由 `apps/web/local-folder-batch.js` 的 `createImportQueue` 提供（无 DOM 依赖、可单测）；`app.js` 只负责渲染队列面板和把每项接到现有上传/创建流程。
- 单个商品失败时清理其未完成上传会话，记录错误并继续下一个商品。
- 所有商品都失败时显示错误；部分成功时显示成功数和失败数，并保留失败商品名称。

## 错误处理

- 没有可支持素材时沿用现有错误提示。
- 超出单会话文件数、单文件大小或总大小限制时，只使对应商品失败。
- 上传或创建失败不回滚已经成功创建的其他商品。
- 用户重新选择同一目录时创建新的上传会话；现有基础商品重复处理规则保持不变。

## 测试

- 前端静态/行为测试覆盖：多个一级商品目录的分组、单商品兼容、根目录文件忽略、嵌套路径保留、逐项失败继续、进度与汇总文案。
- `tests/local_folder_batch.test.cjs` 覆盖队列：串行不并发、后入队排在正在跑的商品之后、失败不阻塞后续、等待项可移除/清空、通知时序。
- 后端现有上传安全和完整性测试继续通过。
- 执行相关前端测试及 `tests/test_local_folder_uploads.py` 回归测试。

## 不在本次范围

- 从系统文件选择窗口直接 Ctrl/Shift 多选任意、不相邻的文件夹。
- 递归把商品目录内部的每一级子目录继续拆成商品。
- 跨页面/跨浏览器持久化的导入队列（当前队列只活在页面生命周期内），以及暂停/恢复正在进行的项。
- 后端持久化的导入任务（NAS 走 `from-folders` 后台任务，本地导入仍是前端队列 + 现有单商品接口）。
