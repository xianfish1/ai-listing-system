# 视觉导入属性详情描述设计

## 目标

从 NAS 商品文件夹或本地文件夹上传创建基础商品时，使用产品图识别商品属性，并将识别结果默认写入商品 `description`。详情描述只保留 ERP 可直接使用的属性行，不保留模型生成的营销文案。

## 行为范围

- NAS 路径导入 `/api/base-products/from-folder` 与本地文件夹上传完成接口 `/api/local-folder-uploads/{upload_id}/complete` 继续使用同一视觉识别流程。
- 视觉模型继续返回标题、描述和属性 JSON，以保持现有模型协议兼容。
- 服务端在“生成详情描述”开启且识别到属性时，仅使用规范化后的属性渲染详情描述：每行 `属性名 : 属性值`，属性之间使用一个空行。
- 例如：

  ```text
  Applicable Season : Four Seasons

  Applicable Scene : Daily

  Material : Polyester
  ```

- 识别到的属性仍可保存到内部 `recognized_attributes` 字段，作为兼容和调试数据；该字段不作为详情描述的替代展示内容。
- “填写属性到详情描述”默认开启，已有显式关闭设置或请求级覆盖时不写入属性描述。
- 未识别到属性时不生成空白或伪造描述；保留原有描述和现有错误/提示行为。

## 数据流

1. 文件夹扫描器建立基础商品和素材索引。
2. `_enrich_with_vision_listing` 调用视觉生成服务。
3. 视觉生成服务解析模型 JSON，规范化属性键值。
4. 当描述生成和属性填充均启用时，以属性块作为完整 `description`，不拼接模型 prose。
5. 基础商品更新 `description`，并按兼容策略保存 `recognized_attributes`。

## 错误处理

- AI 连接缺失、图片不可读、网关异常或 JSON 无效均不得阻断基础商品创建。
- 失败时沿用 `ai_generation_error`，不覆盖原有商品描述。
- 属性键值继续受现有数量、键长度和值长度限制。

## 测试要求

- 更新视觉生成单元测试，验证属性描述只包含格式化属性行，不包含模型 prose。
- 保留现有格式、开关关闭、空属性和错误路径测试。
- 更新导入 API/本地上传测试，验证两条导入路径均能得到属性-only 描述。
