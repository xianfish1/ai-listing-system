# 店铺刊登副本标题与图片差异化设计

> **图片差异化不实施（2026-09-20）：** 操作员要求刊登图片严格按「商品维护 → 产品图顺序」
> 出图，图片顺序不再按店铺种子重排；副本创建时按 `template_id` 打乱第 2..N 张的实现已从
> `services/api/storage.py` 移除。标题/卖点短语差异化从未落地，本设计只留作历史参考。

## 目标

同一个基础商品复制到不同店铺模板时，为每个店铺生成稳定但不同的刊登副本：

- 商品主图保持不变。
- 只重新排列第 2、3、4、5 张商品图。
- 标题核心词及其顺序保持不变。
- 只重新排列操作员明确配置的卖点短语。
- 同一基础商品复制到同一店铺模板时，生成结果稳定，不因重试而反复变化。

本功能只影响新创建的店铺刊登副本，不修改基础商品、已有副本或已有自动化任务。

## 基础商品字段

基础商品增加两个可维护字段：

- `title_core`：核心标题，作为不可拆分的完整文本固定在标题开头。
- `title_selling_points`：可重排卖点短语数组，每个元素作为不可拆分的短语参与排序。

示例：

```json
{
  "title_core": "Hatsune Miku Pixel Style T-shirt",
  "title_selling_points": [
    "Pure Cotton",
    "Printed",
    "Loose Fit",
    "Casual"
  ]
}
```

系统不得按单词自动拆分完整标题，也不得猜测角色名、品牌名或品类词。卖点短语由操作员明确录入，每行一个；保存时去除空白项和大小写不敏感的重复项，但保留操作员输入的短语内部顺序与大小写。

## 标题生成规则

创建店铺刊登副本时：

1. 如果 `title_core` 和至少一个卖点短语都有值，使用结构化标题生成。
2. 核心标题固定在开头，不改变其内部词序。
3. 卖点短语使用稳定种子重新排列，然后以单个空格拼接在核心标题之后。
4. 如果没有核心标题或没有卖点短语，完整沿用基础商品当前的 `listing_title`，不做自动拆词。
5. 如果基础商品没有 `listing_title`，继续沿用当前的默认标题回退规则。

示例结果：

```text
Hatsune Miku Pixel Style T-shirt Pure Cotton Casual Printed Loose Fit
Hatsune Miku Pixel Style T-shirt Loose Fit Printed Pure Cotton Casual
```

## 图片生成规则

创建店铺刊登副本时：

1. 先规范化基础商品的 `product_images`，保持现有去重和数量限制。
2. 第 1 张图片固定不变，并同步保存为副本 `main_image`。
3. 只重排索引 1 至 4，即用户看到的第 2 至第 5 张图片。
4. 第 6 张及后续图片保持原顺序。
5. 商品图少于 5 张时，只重排实际存在的第 2 张至最后一张。
6. 商品图少于 3 张时不需要产生可见差异，但仍按同一规则返回有效顺序。

尺码图和颜色变体图不参与本次排序。

## 稳定差异算法

标题卖点和商品图片使用同一个稳定洗牌约束，但分别使用独立命名空间，避免两个结果相互影响。

稳定种子由以下字段组成：

```text
基础商品 ID + 店铺模板 ID + 用途命名空间
```

用途命名空间分别为：

- `listing-title-selling-points-v1`
- `listing-product-images-v1`

实现使用 SHA-256 生成确定性排序权重，不使用进程级随机数或 Python `hash()`。因此：

- 相同基础商品与相同模板每次得到相同结果。
- 不同模板通常得到不同结果。
- 服务重启、部署到不同机器后结果不变。

当多个店铺模板在同一次复制请求中因短语或图片数量太少而产生相同排列时，不强行破坏稳定性。系统不承诺所有店铺排列绝对唯一，只承诺以店铺模板为种子的稳定差异化。

## 数据归属与兼容

- 基础商品保存原始 `listing_title`、`product_images`、`title_core` 和 `title_selling_points`。
- 店铺刊登副本保存生成后的完整 `listing_title` 和 `product_images` 快照。
- 副本第一张 `product_images` 必须与 `main_image` 一致。
- 用户在副本维护编辑器中的后续修改优先，系统不再次自动洗牌。
- 更新基础商品或模板时，不重写已有副本的标题和图片顺序。
- 已创建自动化任务继续使用不可变执行快照。
- 旧基础商品缺少新字段时，行为与当前版本完全一致。

## 界面

“基础商品维护”弹窗增加：

- `核心标题` 单行输入框。
- `可重排卖点` 多行输入框，每行一个短语。

界面保存这两个字段，并在重新打开维护弹窗时正确回显。店铺刊登副本编辑器继续显示最终生成的完整标题和图片顺序，不增加额外随机化按钮。

## API 与校验

基础商品更新 API 接受：

```json
{
  "title_core": "Hatsune Miku Pixel Style T-shirt",
  "title_selling_points": ["Pure Cotton", "Printed", "Loose Fit", "Casual"]
}
```

存储层负责：

- 将 `title_core` 规范化为去除首尾空白的字符串。
- 将字符串或数组形式的卖点规范化为短语数组。
- 去除空项与重复项。
- 限制卖点数量为 12 个，每个短语最长 80 个字符，核心标题最长 300 个字符。
- 超出限制时返回明确校验错误，不截断核心商品信息。

## 测试标准

自动化测试至少覆盖：

1. 同一基础商品复制到两个不同店铺模板时，主图相同。
2. 两个副本只在第 2 至第 5 张图片范围内重新排序，第 6 张以后不变。
3. 相同基础商品与模板重复计算得到相同标题和图片顺序。
4. 核心标题在所有副本中逐字保持不变且固定在开头。
5. 卖点短语作为整体移动，短语内部不被拆分。
6. 缺少核心标题或卖点时沿用当前完整标题。
7. 已存在副本不因基础商品后续修改而变化。
8. 基础商品维护页面能保存并回显两个新字段。
9. Browser-Use 任务载荷使用副本最终标题、固定主图和差异化图片顺序。

## 非目标

- 不使用 AI 生成或改写标题。
- 不自动识别完整标题中的核心词。
- 不保证每个店铺的排列绝对唯一。
- 不打乱主图、尺码图、颜色变体图或第 6 张以后的商品图。
- 不改写已有副本和已有自动化任务。
