# 店铺模板、AI 描述与马帮保存闭环设计

## 1. 状态与优先级

本设计已经过逐节确认，覆盖商品维护、店铺模板、马帮真实采集、AI 描述、店铺刊登副本、自动化任务和 Worker 保存草稿的完整闭环。

发生冲突时，本设计取代以下旧结论：

- `2026-07-05-product-line-template-design.md` 中面向操作员的产品线和标题后缀流程。
- `2026-07-12-category-profile-rules-design.md` 中类目规则需要人工审核发布、自动化停在保存前的流程。
- `2026-07-13-mabang-auto-worker-save-draft-design.md` 中与本设计的就绪状态、任务快照和成功后关闭页面不一致的部分。

未发生冲突的既有实现和安全约束继续有效，特别是禁止发布、保存成功证据和任务租约规则。

## 2. 目标

- 平台类目、类目必填规则和店铺促销活动全部来自马帮真实登录态，不使用伪造目录。
- 店铺模板集中维护店铺刊登所需默认值，并能按类目表达不同必填项。
- 一个基础商品可以一次复制到多个完整的店铺模板，每个模板产生独立的店铺刊登副本。
- 店铺刊登副本在人工检查和保存后，才允许手动生成自动化任务。
- AI 描述在副本创建阶段生成并保存，自动化执行阶段不调用 AI。
- Worker 自动领取任务、完整填表、只点击保存；保存成功后关闭当前页面并继续下一任务。
- 模板、规则、活动或模型变化不会静默修改已有副本和在途任务。

## 3. 非目标

- 不让 Worker 点击保存并刊登、刊登、发布或提交审核。
- 首期不开发浏览器插件，继续复用现有 Chrome/CDP 登录环境。
- 不允许模板或操作员直接维护马帮原始 ID。
- 不在首期实现任意协议的通用模型代理；首期只实现 Anthropic Messages API 兼容协议，保留新增适配器的接口。
- 不自动修复未知必填值、不自动替换过期活动、不自动迁移已有副本到新规则。
- 不在系统故障时让 Worker 无限制跳过错误并继续运行。

## 4. 领域对象与数据归属

| 对象 | 归属与职责 | 版本规则 |
| --- | --- | --- |
| AI 模型连接 | 管理员维护协议、接口地址、密钥、模型 ID 和启用状态 | 修改地址或模型生成新修订；密钥轮换不改变业务版本 |
| 描述生成方案 | 保存中文名称、生成模式、提示词、固定段落和受保护事实 | 每次业务内容修改生成新版本 |
| 平台类目目录 | 保存马帮真实类目层级、叶子状态和隐藏 ID | 每次完整采集生成目录快照 |
| 类目规则版本 | 保存一个店铺、平台站点和叶子类目的字段定义、必填条件和变体规则 | 有效采集后自动激活，旧版本保留 |
| 店铺活动目录 | 保存一个店铺的完整促销活动集合 | 重新采集更新状态并保留历史，不静默替换模板选择 |
| 店铺模板版本 | 保存店铺刊登默认值及其引用的类目规则和描述生成方案 | 编辑或从马帮更新时生成新版本 |
| 店铺刊登副本 | 保存从基础商品和一个模板产生的可编辑草稿 | 创建时快照所有输入；编辑保存形成副本修订 |
| 自动化任务 | 保存一次不可变的马帮表单执行输入 | 创建后不可修改；修改数据必须取消并重建任务 |

### 4.1 AI 模型连接

模型连接至少包含：

- 可读连接名称。
- `anthropic_messages` 协议标识。
- 基础接口地址。
- 加密保存的 API Key。
- 模型 ID。
- Anthropic API 版本。
- 超时、启用状态、默认标记和连接修订号。

系统可以配置多个连接，但任何时刻最多一个系统默认连接。描述生成方案可由管理员绑定一个连接；未绑定时跟随系统默认连接。切换默认连接只影响之后的生成请求，不修改已经保存的描述。

### 4.2 描述生成方案版本

模板操作员只选择中文描述生成方案，不接触协议、API Key 或原始模型 ID。方案版本包含：

- `组合生成` 或 `完全生成`。
- 系统提示词和商品段生成规则。
- 固定开场、固定售后条款。
- 发货时间、包装数量和售后承诺等受保护事实。
- 输出语言、最大长度和允许的 HTML 格式。
- 可选的管理员级模型连接绑定。

店铺模板引用明确的描述生成方案版本。方案发布新版本后，旧模板显示可更新，但不会自动变化。

### 4.3 店铺模板版本

店铺模板版本保存：

- 店铺和可读模板名称。
- 平台、站点、叶子类目和类目规则版本。
- 类目必填值和变体默认值。
- 默认促销活动。
- 原价和 `优惠 40%` 定价规则。
- 库存、重量、包裹长宽高。
- 预设尺码和自定义尺码。
- 尺码图资产版本。
- 描述生成方案版本。
- SKU 格式及其他已确认的刊登默认值。

遗留产品线、标题后缀和原始马帮编号只为兼容旧数据保留，不显示、不编辑、不筛选，也不影响新流程。

### 4.4 店铺刊登副本

每次选择一个店铺模板，就创建一个独立副本。副本快照包含：

- 基础商品身份和商品资产版本。
- 店铺模板版本。
- 类目路径、类目规则版本、字段定义和值。
- 活动可读信息及隐藏 ID。
- 原价、六折售价和币种精度。
- SKU、颜色、尺码、库存、重量和包裹尺寸。
- 尺码图实际文件版本。
- 描述生成方案版本、生成结果和实际模型元数据。

模板、图片、活动、规则或模型之后发生变化时，已有副本不自动改变。操作员必须显式应用新版本并重新检查。

### 4.5 自动化任务

任务从已保存且通过就绪检查的副本创建，保存完整执行快照和快照哈希。一个副本最多存在一个 `ready`、`claimed`、`running` 或 `needs_confirmation` 状态的活动任务。

已创建任务不跟随副本编辑。需要修改时先取消旧任务，再从最新副本修订生成新任务。

## 5. 操作流程

### 5.1 管理员配置 AI

1. 管理员打开“AI 模型连接”。
2. 新增连接名称、Anthropic 兼容地址、API Key、模型 ID 和 API 版本。
3. 点击“测试连接”；测试只发送最小请求，不写入商品数据。
4. 测试成功后启用连接，可将其设为默认。
5. 管理员创建描述生成方案版本，并选择生成模式与受保护事实。

API Key 在页面中始终显示为掩码。日志、任务、生成记录和错误响应都不得返回密钥。

### 5.2 从马帮当前页面导入模板

1. 操作员在专用 Chrome 中登录马帮，打开商品新建或编辑页面。
2. 操作员在马帮手动选择店铺、平台类目、必填值和默认活动。
3. 回到系统点击“从马帮当前页面导入模板”。
4. 系统确认当前只有一个可识别的马帮商品编辑页，并执行只读采集。
5. 系统采集当前选择、必填规则、完整店铺活动目录和真实类目目录。
6. 数据完整且结构校验通过后，类目规则版本自动激活并创建或更新店铺模板草稿。
7. 同一店铺和类目已有模板时，弹窗默认选择“更新现有模板”，也允许“另存为新模板”。

导入过程中不得触发保存、发布、提交、确认或任何会改变马帮商品状态的请求。

### 5.3 编辑店铺模板

店铺模板页面提供以下操作区：

- 可搜索、可展开的平台类目弹窗，只允许选择叶子类目。
- 动态类目必填项表单。
- 店铺促销活动选择器。
- 原价与自动计算的六折售价预览。
- 库存、重量和包裹长宽高。
- 尺码复选框和自定义尺码。
- 尺码图缩略图、替换和上传。
- 描述生成方案选择器。
- 完整性检查和缺项列表。

未采集的叶子类目可以选中，但模板状态变为 `需要从马帮导入`。没有可用活动时显示 `活动未配置`。缺少其他必填值时显示 `需要补充`。

### 5.4 从商品复制到多个模板

1. 商品维护页面点击“复制到店铺模板”。
2. 弹窗按店铺、模板名和类目搜索，并显示活动、价格、尺码和完整性。
3. 不完整模板保持可见但禁止勾选，同时展示缺项原因。
4. 操作员勾选一个或多个完整模板并确认。
5. 系统为每个模板分别创建一个店铺刊登副本。
6. 每个副本分别调用一次描述生成；一个副本失败不回滚其他已创建副本。

AI 失败的副本状态为 `描述待生成`，仍可打开、手工编辑或重试生成，但不能创建自动化任务。

### 5.5 检查副本并生成任务

操作员在店铺刊登副本中检查和编辑类目属性、活动、价格、SKU、交易信息、尺码图和描述。保存只更新副本，不自动排队。

当副本通过就绪检查后，操作员点击“生成自动化任务”。系统再次校验最新规则和活动状态，保存不可变任务快照并进入 `ready`。

### 5.6 Worker 保存循环

1. Worker 原子领取最早的 `ready` 任务并取得租约。
2. Worker 检查 Chrome、登录态、任务快照、规则版本和活动有效性。
3. Worker 打开马帮商品页，按快照完整填写表单。
4. Worker校验店铺、类目、图片、SKU、价格、活动和交易信息。
5. Worker 只点击精确匹配的“保存”，禁止任何发布动作。
6. 保存成功证据满足要求后，任务进入 `saved`。
7. Worker 关闭当前任务页面，释放租约并继续领取下一任务。

## 6. 马帮真实数据采集

### 6.1 类目目录

平台类目目录必须来自马帮登录态下的真实数据。采集优先复用页面已经调用的类目接口；接口无法稳定复用时，读取页面已经加载的结构化状态或逐层展开只读控件。

每个类目节点保存：

- 中文名称和完整路径。
- 父节点、层级和排序。
- 是否为叶子类目。
- 平台、站点和采集时间。
- 隐藏的马帮类目 ID。
- 采集来源和目录快照版本。

开发 fixture 只能用于测试解析器，不得作为生产类目数据写入。目录未采集或已被判定无效时，界面不得展示系统编造的替代类目。

### 6.2 类目规则

类目规则采集保存字段稳定 ID、中文名称、控件类型、必填状态、条件必填表达式、选项、当前选值、页面映射和变体规则。

采集器只支持结构化、可验证的字段类型和条件。字段身份冲突、条件无法表达、必填字段缺少页面映射或解析不完整时，本次运行失败，不激活部分版本。

有效版本自动激活，不再包含审核人、审核备注、批准或拒绝状态。新版本增加无默认值的必填项时，相关模板标记为 `需要补充`；已有副本保留快照，但在生成新任务前必须显式应用新规则并补齐字段。

### 6.3 店铺活动目录

一次页面导入采集所选店铺的完整活动目录，而不是只保存当前活动。每项活动保存：

- 中文活动名称。
- 折扣的可读表达，例如 `六折（优惠 40%）`。
- 开始和结束时间。
- 可用、未开始、已过期或停用状态。
- 隐藏的内部活动 ID。

界面标签由名称、折扣和有效期组成。重新采集发现活动过期时只更新状态，不自动替换模板和副本的活动。

### 6.4 采集失败

采集运行保存阶段、页面地址的去敏版本、页面结构版本、失败代码和诊断截图。登录失效、目标标签页不明确、接口失败、页面解析不完整或出现写操作风险时立即停止。

失败运行不得覆盖当前有效目录、规则或活动数据。

## 7. AI 描述架构

### 7.1 内部 AI 网关

业务层只依赖统一接口：

```text
generate_description(request, profile_version, connection_revision) -> GenerationResult
```

协议适配器负责请求格式、鉴权头、响应解析和协议错误归一化。首期实现 Anthropic Messages API 兼容适配器，向连接的 `/v1/messages` 端点发送标准 `system`、`messages`、`max_tokens` 和 `temperature` 字段，并解析文本内容块。

现有 `DeepSeekAdapter` 的提示构建和本地校验逻辑可以迁移复用，但业务层不得继续直接依赖 DeepSeek、OpenAI Chat Completions 响应或环境变量中的单一模型。后续需要直连 DeepSeek 原生接口时，新增 OpenAI 兼容适配器，不修改模板和副本模型。

### 7.2 组合生成

组合生成由三段组成：

1. 描述生成方案中的固定开场。
2. AI 生成的商品专属介绍。
3. 描述生成方案中的固定售后条款。

AI 只返回第二段。固定开场、发货承诺和售后条款不进入 AI 可编辑输出。

### 7.3 完全生成

完全生成允许 AI 决定普通文案的结构和措辞，但受保护事实由系统持有并注入，至少包括：

- 发货时间。
- 包装数量和包装内容。
- 售后承诺。

AI 输出使用一次性事实占位符；系统要求每个占位符恰好出现一次，再用规范事实块替换。AI 不得生成额外的发货时间、包装数量或售后承诺。

### 7.4 输入与输出

生成输入来自基础商品和店铺模板快照，包括商品名称、类目、属性、颜色、尺码、包装内容和目标语言。不得把浏览器会话、马帮 ID、API Key 或自动化步骤发送给模型。

生成结果保存为经过清理的 HTML 或纯文本。只允许描述方案声明的安全标签；HTML 实体在自动化边界统一编码，避免重复转义。

### 7.5 校验与失败

确定性校验至少检查：

- 结果非空且长度合规。
- 必需事实块完整且只出现一次。
- 不存在冲突的发货时间或包装数量。
- 不存在未经配置的新售后承诺。
- HTML 标签和链接符合白名单。
- 模型输出不包含提示词、JSON 包装或错误文本。

校验失败或模型不可用时不静默切换其他模型。副本进入 `描述待生成`，操作员可切换系统默认连接后重试，也可手工填写。重新生成覆盖当前描述前必须确认，旧版本保留。

每次生成记录方案版本、连接修订、连接名称、模型 ID、耗时、结果状态和去敏错误。API Key 永不进入生成记录。

## 8. 定价、尺码、尺码图与交易信息

### 8.1 定价

操作员输入原价，系统计算售价：

```text
售价 = 原价 x 0.60
```

界面显示 `六折（优惠 40%）`。金额按店铺币种的最小单位使用十进制定点舍入，禁止使用二进制浮点直接落库。

### 8.2 尺码

标准复选框为：

`100`、`110`、`120`、`130`、`140`、`150`、`S`、`M`、`L`、`XL`、`XXL`、`XXXL`。

操作员可以添加 `160`、`4XL` 等自定义尺码。自定义值去除首尾空格后按不区分大小写去重，并保存为该模板可重复使用的复选框。

### 8.3 尺码图

尺码图归店铺模板所有。模板页面显示缩略图并支持上传或替换。新图片只影响之后创建的副本；已有副本继续引用创建时的图片版本，除非操作员在副本中显式替换。

### 8.4 交易信息

店铺模板必须提供一套统一默认值：

- 库存。
- 重量，单位 kg。
- 包裹长度、宽度和高度，单位 cm。

这套值应用于全部 SKU，副本可整体编辑。自动化把它们写入马帮 `交易信息`。执行器不得再提供 `999`、`0.25` 或 `28 x 22 x 2` 等硬编码回退。

## 9. 就绪状态

### 9.1 店铺模板

| 状态 | 条件 | 是否可用于复制 |
| --- | --- | --- |
| `需要从马帮导入` | 类目未采集或没有有效规则 | 否 |
| `活动未配置` | 没有可用活动或未选择活动 | 否 |
| `需要补充` | 类目值、交易信息、尺码、所需图片或描述方案不完整 | 否 |
| `可使用` | 所有模板检查通过 | 是 |

### 9.2 店铺刊登副本

副本检查基础商品、图片、SKU、价格、类目规则和值、活动、交易信息、尺码图和描述。AI 未成功且没有手工有效描述时显示 `描述待生成`。

保存副本不生成任务。只有状态为 `可生成任务` 时，按钮才可用。

### 9.3 任务创建和执行前检查

创建任务时重新检查：

- 副本是最新已保存修订。
- 当前有效类目规则与副本快照一致。
- 活动仍可用且未过期。
- 描述和受保护事实有效。
- 没有同副本活动任务。

Worker 执行前重复检查快照哈希、规则版本和活动状态。配置已过期时停止任务，不自动改写输入。

## 10. Worker、安全与错误状态

### 10.1 领取和租约

Worker 通过原子状态变更领取任务，状态流转为：

```text
ready -> claimed -> running -> saved
                          -> failed
                          -> needs_confirmation
ready/claimed -> canceled
legacy queued task without snapshot -> needs_regeneration
```

领取记录 Worker ID、租约截止时间和心跳。只有租约过期后，其他 Worker 才能重新领取。一个 Chrome Profile 首期只运行一个保存 Worker。

内部状态与中文显示固定映射如下：

| 内部状态 | 中文显示 |
| --- | --- |
| `ready` | 待领取 |
| `claimed` | 已领取 |
| `running` | 执行中 |
| `saved` | 已保存 |
| `failed` | 执行失败 |
| `needs_confirmation` | 需要人工确认 |
| `needs_regeneration` | 需要重新生成 |
| `canceled` | 已取消 |

### 10.2 保存保护

- 允许动作只精确匹配“保存”。
- 捕获阶段拦截“保存并刊登”“刊登”“发布”“提交审核”等按钮和程序化点击。
- 保存 token 单次有效，防止重复点击。
- 保存成功至少满足既有规范中的两项独立证据。
- 成功后记录 `publish_clicked=false`，关闭当前任务页面并领取下一项。

### 10.3 错误分类

- 商品级数据错误：当前任务进入 `failed`，保留字段错误和截图，Worker 可以继续下一项。
- 保存结果不明确：任务进入 `needs_confirmation`，不得自动重试保存。
- 登录失效、验证码、页面结构变化、关键按钮识别异常：视为系统故障，暂停 Worker，防止连续失败。
- Worker 进程退出：任务等待租约过期后恢复，不能由两个 Worker 同时执行。

错误界面显示中文业务信息。会话 URL 查询参数、马帮 token、API Key 和内部堆栈只进入受限且去敏的诊断通道。

## 11. API 与模块边界

具体路由命名可遵循现有 API 风格，但必须提供以下能力：

- AI 模型连接的创建、测试、启停、默认切换和密钥轮换。
- 描述生成方案及版本的创建、读取和启用。
- 平台类目目录完整采集、查询和采集状态。
- 马帮当前页面导入、冲突预览、更新模板或另存新模板。
- 店铺活动目录查询和刷新。
- 多模板复制及逐副本生成结果。
- 副本描述重试、手工保存、就绪检查和任务创建。
- 任务取消、领取、心跳、结果回写和人工确认。

建议模块边界：

- `model_gateway`：协议无关的生成入口和错误模型。
- `anthropic_messages_adapter`：Anthropic 兼容请求与响应。
- `description_generation`：方案组装、受保护事实注入和结果校验。
- `mabang_page_import`：CDP 页面发现、只读采集和规范化。
- `template_readiness`：模板、副本和任务共用的就绪检查。
- `automation_task_service`：不可变快照、唯一活动任务和租约。
- `browser_executor`：消费任务快照并执行保存，不依赖 AI 服务。

## 12. 迁移

迁移前暂停 Worker 并备份 JSON/Postgres 数据和当前任务状态。迁移脚本必须支持 `dry-run`、幂等执行、逐对象结果和恢复说明。

迁移规则：

- 旧静态或无法证明来源的类目保留为历史数据，但标记 `需要从马帮导入`，不能继续冒充真实目录。
- 旧模板保留原始马帮 ID 和遗留字段用于兼容读取，前端全部隐藏。
- 缺少活动、库存、重量、包裹尺寸、尺码或有效规则的模板标记 `需要补充`。
- 不把执行器旧硬编码回退写进模板。
- 已有描述保留；空描述副本标记 `描述待生成`。
- 已完成任务保留为历史记录。
- 缺少不可变快照的旧排队任务标记 `需要重新生成`，不交给新 Worker 执行。
- 迁移不删除旧字段；新流程只写新结构，稳定运行后再单独设计清理。

## 13. 测试

### 13.1 单元测试

- 两个真实类目具有不同字段集合和条件必填结果。
- 类目规则自动激活、新增必填项和模板缺项状态。
- 活动未配置、未开始、过期和停用状态。
- 原价乘以 `0.60` 及不同币种精度。
- 标准尺码、自定义尺码去重和 SKU 展开。
- 组合生成拼接、完全生成事实占位符和冲突事实拦截。
- Anthropic 响应解析、去敏错误和模型连接切换。
- 模板、副本和任务三层快照不互相静默修改。
- 同副本活动任务唯一性和租约过期。

### 13.2 集成测试

- 当前页面导入成功、重复导入更新、另存新模板和失败不覆盖。
- 完整店铺活动目录采集及过期活动不自动替换。
- 多模板复制中部分 AI 失败，其余副本仍成功创建。
- 描述重试保留旧版本，手工描述通过相同校验。
- 规则升级或活动过期阻止任务创建。
- Worker 领取、心跳、租约恢复和不可变 payload。

### 13.3 采集器与浏览器测试

- 使用脱敏的真实马帮接口响应和页面快照回放采集器。
- 测试断言导入阶段没有保存、发布、提交或确认请求。
- 保存 Worker 完整填写交易信息、活动、图片、变体和 SKU。
- 保存成功后关闭任务页并继续下一任务。
- 保存结果不明确不重试；登录失效和页面结构变化暂停 Worker。
- 桌面和移动视口检查类目弹窗、多模板弹窗、缩略图和错误文本无重叠。

## 14. 生产试运行

1. 暂停 Worker，备份并运行迁移 `dry-run`。
2. 应用迁移并核对模板、副本和旧任务状态。
3. 配置一个 Anthropic 兼容模型连接并通过健康测试。
4. 在真实马帮登录态下采集目标店铺完整类目目录和活动目录。
5. 从当前页面导入一个真实店铺模板，补齐交易信息、尺码和尺码图。
6. 选择一个测试商品创建副本，生成并人工检查描述。
7. 手动生成一个任务，由单 Worker 完整填写并只保存草稿。
8. 核对保存证据、马帮草稿、任务日志、页面关闭和下一任务领取。
9. 观察保存成功率、失败步骤、任务耗时、租约恢复和重复任务数后，再扩大店铺范围。

任何试运行步骤都不包含正式发布。

## 15. 验收标准

- 类目选择器展示马帮真实完整目录，不包含硬编码伪造类目。
- 不同叶子类目展示并校验不同必填项。
- 店铺活动按店铺隔离，以中文名称、折扣和有效期展示，原始 ID 隐藏。
- 产品线、标题后缀和马帮原始编号不出现在新操作流程。
- 店铺模板可维护库存、重量、包裹尺寸、复选尺码、自定义尺码和尺码图。
- 商品维护可以一次选择多个完整模板，并为每个模板生成独立副本和描述。
- 描述支持组合生成和完全生成，受保护事实无法被模型篡改。
- 管理员可通过 Anthropic 兼容配置自由切换模型，切换不改变历史描述。
- 副本可编辑、检查和保存，保存本身不自动生成任务。
- 不完整副本不能生成任务，错误信息能指出具体缺项。
- Worker 自动领取任务，完整填表后只保存草稿；成功后关闭页面并继续下一任务。
- 保存不明确不重复点击，系统故障会暂停 Worker。
- 全流程没有发布行为，日志记录 `publish_clicked=false`。

## 16. 实施顺序

1. 数据模型、迁移和统一就绪检查。
2. AI 模型连接、Anthropic 适配器、描述方案和生成校验。
3. 马帮真实类目、规则和活动采集及模板导入。
4. 店铺模板页面和多模板复制弹窗。
5. 店铺刊登副本编辑、描述重试和任务创建。
6. Worker 新快照消费、保存后关闭页面和异常暂停。
7. 自动测试、真实单店试运行和分阶段扩展。

每一阶段必须先完成自动测试和数据兼容验证，再进入下一阶段。生产扩展以真实保存草稿证据为准，不以模拟页面通过代替实地验收。
