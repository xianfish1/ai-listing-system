# 跨境与本土店铺 readiness 区分设计

## 背景

店铺刊登副本和自动化任务目前共享 readiness 展示与部分校验字段。跨境 CNSC 与本土 site 的业务字段不同，公共路径可能把另一种店铺的缺项显示出来，例如本土显示 CNSC 站点价格配置，或跨境显示本土促销、尺码图提醒。

本次目标是让两种模式的缺项和提醒严格按店铺类型隔离，同时保留类目属性的具体字段 ID，便于补填 `100022`、`100134`、`100168` 等必填项。

## 判定规则

- `listing_mode == "cnsc_global"` 唯一表示跨境 CNSC。
- 其他值统一视为本土 `site`，不依据店铺名称、国家或货币猜测类型。

## 校验边界

### 跨境 CNSC

保留基础资料、SKU、类目快照必填属性、跨境站点店铺、站点促销活动、全球价/站点价格矩阵、三仓库存和跨境专用配置校验。

不读取本土 `mabang_discount_id` / 普通 `promotion_activity_id`、普通 SKU 价格缺项或本土尺码图缺项作为跨境 readiness 缺项。

### 本土 site

保留基础资料、普通 SKU、类目快照必填属性、本土店铺促销、普通价格、库存、物流信息和尺码图校验。

不读取 CNSC 目标站点活动、全球价/站点价格矩阵、三仓库存或跨境专用配置作为本土 readiness 缺项。

## 展示契约

- 类目错误字段继续输出为 `category_attributes.<field_id>`，前端展示为 `必填类目属性未填写：<field_id>（<属性名>）`。
- 枚举外的自选值（原产地=Philippines）不是错误：输出为提醒字段 `category_custom_option.<field_id>`（只进 `warnings`，建任务时写入 `job.warnings`），前端展示为 `类目属性「<属性名>」使用了枚举外的自选值，执行时按马帮「自填选项」写入`。采集端会把页面上的自填值并入枚举、执行器走 `select_custom`，所以不阻塞。
- 促销目录无法解析的跨境提醒继续显示完整文案：`提醒：促销活动未解析（促销目录中未找到该活动），执行时可能失败`。
- 本土促销只显示本土促销状态；跨境不显示公共本土促销状态。
- 尺码图提醒只在本土 readiness 必需时产生；跨境不因本土尺码图字段缺失而阻塞。
- 后端 readiness 是最终事实来源，前端只负责按字段渲染，不依据店铺名称二次判断。

## 实现与验证

1. 在现有 `_check_automation_readiness` 的公共字段集合处按模式建立隔离分支，保持现有跨境专用配置校验和本土通用校验逻辑。
2. 调整运行时促销状态补充逻辑，使两种模式只进入对应的促销分支。
3. 先增加失败回归测试，再实现：覆盖本土排除 CNSC 字段、跨境排除本土促销/尺码图字段，以及类目属性 ID 展示。
4. 运行相关 Python readiness、类目、CNSC 流程测试和前端静态契约测试。

## 不在范围内

- 不改马帮页面执行器的字段填写流程。
- 不改变已有字段名称、API 路径或历史数据迁移格式。
- 不根据店铺名称新增类型推断规则。
