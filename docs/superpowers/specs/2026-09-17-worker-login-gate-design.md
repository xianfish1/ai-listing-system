# Worker 启动与登录门禁设计

## 目标

启动自动化 Worker 时，系统必须先按当前设置准备专用采集浏览器并确认马帮已经登录。只有登录确认成功后，Worker 才能启动或恢复并领取任务。登录失败时，任务保持未领取，不进入执行阶段。

## 已确认的行为

- `mabang.headless=true` 时，采集/Worker 浏览器必须以无头模式启动。
- `mabang.headless=false` 时，采集/Worker 浏览器以窗口模式启动。
- 启动 Worker 的固定顺序是：准备浏览器、检查登录、必要时自动登录、确认登录成功、启动 Worker、领取任务。
- 马帮账号已绑定时，系统自动完成登录；不依赖人工验证码流程。
- 登录失败、登录状态不明确或浏览器不可用时，不启动或恢复 Worker，不领取任务。
- Worker 长时间运行期间，在领取任务前再次确认登录状态，防止会话过期后误执行。

## 根因

当前 `/api/worker/start`、`/api/worker/resume` 和重启入口只操作 Worker 进程，没有把浏览器准备和登录确认作为启动门禁。Worker 现有预检主要判断 CDP 端口是否可连接；只要 9223 端口可达，即使连接的是错误配置目录、错误窗口模式或未登录页面，也可能继续领取任务。现场状态中，`mabang.headless` 已开启，但 9223 端口仍由旧的有界面测试浏览器占用，Worker 随后以 `workspace_frame_not_unique` 失败并暂停。

## 方案

采用双层门禁：API 启动门禁负责首次启动和清晰反馈，Worker 领取门禁负责运行期兜底。浏览器启动、模式校验和自动登录复用同一个后端准备函数，避免不同入口产生不同结果。

### 1. 浏览器准备

后端读取当前运行配置中的 CDP 地址、无头开关和专用浏览器配置目录，然后调用采集浏览器启动逻辑。

如果 CDP 已被占用，系统核对占用进程是否属于当前采集浏览器，并核对配置目录、调试端口和无头模式是否与设置一致。发现旧的采集浏览器模式或配置目录不一致时，只终止匹配该采集端口或专用配置目录的 Chrome 进程，再按当前设置启动；不得影响普通 Chrome。

### 2. 登录确认

浏览器可连接后，调用现有自动登录流程。自动登录脚本负责判断当前页面：

- 已登录：返回 `already_logged_in`。
- 未登录：使用已绑定账号登录，成功后返回 `logged_in`。
- 无账号、登录失败或状态无法确认：返回失败状态。

只有 `already_logged_in` 和 `logged_in` 属于门禁通过状态。

### 3. Worker 启动门禁

`start`、`resume` 和 `restart` 在操作 Worker 进程前调用统一的浏览器与登录准备函数。

准备成功后才执行原有 Worker 操作。准备失败时返回可操作的错误结果，Worker 保持停止或暂停，已有自动化任务保持 `ready`，不产生领取记录和尝试次数。

API 响应包含浏览器模式、登录状态和失败原因，前端展示“正在准备无头浏览器”“正在检查登录”“登录成功，Worker 已启动”或明确失败原因。

### 4. Worker 领取门禁

Worker 在调用 claim 接口前执行一次登录门禁。启动后的第一次轮询强制检查；之后只在登录状态失效、浏览器恢复或执行器报告登录阻塞时重新检查，避免每三秒重复登录。

登录门禁未通过时，Worker 返回 `waiting_for_login`，不调用 claim。执行过程中若仍遇到明确的登录阻塞，可自动登录并重试当前执行一次；重试仍失败则阻塞该任务并暂停 Worker。

## 数据流

```text
用户启动 Worker
  -> API 读取当前 headless/CDP/账号配置
  -> 校验或重建专用采集浏览器
  -> 检查登录并在需要时自动登录
  -> 登录确认成功
  -> 启动或恢复 Worker
  -> Worker 领取前再次确认登录状态
  -> claim 自动化任务
  -> 执行任务
```

任一浏览器或登录步骤失败时，流程在 claim 之前停止。

## 错误处理

- 未绑定账号：提示在“设置 → 马帮连接”绑定账号，Worker 不启动。
- 浏览器启动失败：返回 Chrome、端口或配置目录相关原因，Worker 不启动。
- 自动登录失败：保留自动登录脚本给出的安全错误摘要，不记录账号或密码。
- 登录状态无法确认：按失败处理，禁止领取任务。
- 无头设置与现有采集浏览器不一致：重建专用采集浏览器后再登录。
- Worker 运行期登录失效：进入 `waiting_for_login`，恢复成功后再领取任务。

## 测试

- 浏览器启动命令在无头配置下包含 `--headless=new` 和固定窗口尺寸。
- 已登录时不重复填写账号，登录门禁通过后启动 Worker。
- 未登录时先完成自动登录，再启动 Worker。
- 无账号、登录失败和状态不明确时不调用 Worker 启动操作。
- 旧的有界面浏览器或错误配置目录占用采集端口时，仅替换专用采集浏览器。
- Worker 登录门禁失败时不调用 claim，任务尝试次数不增加。
- Worker 登录门禁成功后才调用 claim。
- 前端正确展示无头模式、登录阶段、成功和失败反馈。

## 范围

本次只调整采集浏览器、马帮登录和 Worker 启动/领取顺序，不修改自动化任务的商品填写逻辑、任务生成规则或账号密码存储方式。
