# 店铺模板「六折售价」可自定义设计

## 目标

店铺模板「交易信息」的六折售价不再只是只读的六折结果：操作员可以改成任意价（例如原价 380、六折 228 改成 218），本土自动化按模板里这组原价/售价填写马帮。

## 价格规则

1. 售价默认按 原价 × 0.6 预填；操作员改过之后，再改原价不会覆盖手填值；把售价清空即回到「按原价六折」的自动预填。
2. 模板自己那一行照搬操作员填的原价与六折售价；售价留空才退回六折兜底（老模板与页面导入的既有行为不变）。
3. 按尺码单独设了原价的行，售价按模板的同一折扣比例（售价 ÷ 原价）换算，保持各行折扣一致；比例缺失（售价留空或为 0）时按六折。
4. 跨境(CNSC) 价格来自价目表与站点 %OFF，完全不受本次改动影响。
5. 精度：2 位小数四舍五入（HALF_UP）。前端按「分」做整数运算，与后端 Decimal 结果一致（380/218 + 尺码 420 → 240.95）。

## 同步与冻结

- 保存模板时若「交易信息」的原价/六折售价/尺码原价覆盖发生变化，同步到该模板下已有的**本土**副本价格行；跨境模板与跨境副本跳过。
- 只改写「当前值仍等于旧模板算出来的价」的行：操作员在副本价格表里手工改过的行保持不动；默认 SKU(白T恤) 行有自己的价格来源，一律跳过。
- 副本其他字段与已建任务的执行快照仍然冻结：模板编辑不会改变已建任务的生产参数，要用新价就重新建任务（「再次尝试」重建快照）。

## 界面

- 六折售价改为可编辑数字输入（原为只读），占位文案「留空＝按原价六折」，分区说明写明自动化按此售价填写。
- 「按尺码设置价格」的六折售价列是该比例的实时预览：填了原价显示换算结果，没填显示「继承 <模板售价>」。

## 实现边界

- `services/api/storage.py`：`_site_row_prices` + `_site_sale_price_at_template_ratio`（价格的唯一来源，价格行生成与模板价格同步共用）、`_sync_site_template_prices_to_store_copies`（保存模板时外科式同步）。
- `apps/web/app.js`：`storeTemplateSalePriceIsManual` / `applyStoreTemplateRatio` / `sizeSalePreview`；`apps/web/index.html` 去掉 `readonly` 并 bump `app.js?v=`。
- 执行器只读 `listing_prices.sale_price` 写马帮折扣价，本次改动只改价格行的来源，执行器与快照结构不变。

## 验证

- `tests/test_store_template_sale_price.py`：自定义价生效、留空退回六折、尺码覆盖按比例换算、模板改价同步到已有副本且不动手改行、只改原价时售价照搬、跨境不受影响。
- `tests/test_product_line_flow.py::test_template_update_does_not_mutate_existing_copy_or_job`：除价格行外，副本与执行快照仍保持冻结。
- `tests/test_store_template_workflow_ui.py`：售价输入框不再 `readonly`，手填/自动逻辑已接线。
- 浏览器实测（127.0.0.1:8788）：手填 199 后改原价不被覆盖；清空后改原价重新按六折预填；尺码覆盖 420 的预览 240.95 与后端一致。

## 风险与遗留

- 改 `services/api/storage.py` 后必须重启 API 才生效（worker 一并重启）；前端静态文件只需刷新页面。
- 若模板存的是自定义售价而原价后来又被改（例如走 API 的部分更新），比例会随之变化，尺码覆盖行的售价也跟着变——这是「按模板比例换算」的直接结果，界面预览可见。
