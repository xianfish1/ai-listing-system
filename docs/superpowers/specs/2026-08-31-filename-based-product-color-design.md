# 基于文件名的主图与颜色识别设计

## 目标

导入 NAS 文件夹或本地文件夹时，根据产品图片文件名稳定识别主图、颜色图和颜色候选，减少仅依赖目录结构或通用颜色词带来的误判。

## 文件名规则

- `主图-xxx.ext`、`Main-xxx.ext`、`main-xxx.ext`（大小写不敏感）归类为 `asset_type="main"`。
- 主图前缀规则优先于普通颜色词和详情词判断；这些文件进入基础商品的 `product_images`，并参与主图选择。
- `SKU-颜色-xxx.ext`、`sku-颜色-xxx.ext`（大小写不敏感）归类为 `asset_type="variant"`。
- `SKU-` 后取第一个 `-` 分隔段作为颜色候选；例如 `SKU-红色-01.jpg` 提取 `红色`，`SKU-奶油白.jpg` 提取 `奶油白`。
- 不符合上述前缀时，保留现有目录名、中文颜色词和英文颜色词回退逻辑。

## 颜色归一化

- 已知中文颜色沿用确定性映射，例如 `红色` -> `Red`、`杏色` -> `Apricot`、`棕色` -> `Brown`、`深蓝色` -> `DarkBlue`。
- 中文颜色词表与英文同构：根词（白/黑/灰/粉/紫/红/蓝/绿/黄/米/棕/杏/橙/咖啡/藏青/卡其/金/银）加可选「色」后缀，再加可选深浅前缀（深/浅/淡/暗/亮）合成 CamelCase 规范名（`浅蓝色` -> `LightBlue`）；匹配时长写法优先，`深蓝色` 不会被 `蓝色` 抢先命中成 `Blue`。
- 裸颜色字（`白`、`蓝`）只在文件名里自成一段时才识别，`奶油白`、`米白` 这类词表未收录的自造色名保持原样（交给视觉模型翻译）。
- 已知英文颜色规范为首字母大写，例如 `navy` -> `Navy`。
- 深浅前缀与颜色词连写（供应商常见写法 `darkgreen`/`lightblue`）合成 CamelCase 规范名：`darkgreen` -> `DarkGreen`，`lightblue` -> `LightBlue`；前缀与颜色词被空格/连字符分开时（`dark green`）归到同一个名字，避免同一颜色产生两个变体键。多个颜色词并列不合并（`Black Gold` 保持分词）。
- 英文颜色词表覆盖基础色与常见服饰色（brown/apricot/orange/navy/khaki/cream/ivory/wine/gold/silver/teal/coral/olive/maroon/mint/rose/lavender）。
- 颜色规范化（`storage._normalize_recognized_colors`）保留已有的驼峰写法（`PureWhite`/`DarkGreen`），并按其归一化小写或空格写法，不把驼峰压平。
- 颜色词表未覆盖的中文候选先保留原候选；视觉 AI 在生成刊登内容时返回 `source color -> English color` 翻译，并同步更新基础商品的 `recognized_colors` 与同名颜色图映射。扫描阶段或 AI 不可用时不阻断商品创建。
- 同一颜色候选去重；颜色图映射保持文件扫描顺序稳定，避免随机覆盖。

## 数据流与兼容性

扫描器输出的 `asset_type`、`sku_option`、`product_images`、`recognized_colors` 和 `variant_image_map` 字段保持原接口不变。NAS 导入和本地上传均经过同一扫描器，因此无需新增 API 分支或前端协议。

## 视觉命名的一致性要求（2026-09-19 补）

没有颜色名的数字 SKU 图交给视觉模型命名时，以下四条必须同时成立，否则颜色会和图片错配：

1. **顺序**：文件名按自然序（数字段按数值比较，`1 (2).png` 在 `1 (10).png` 前）。字典序会把
   `1 (10).png` 排到第二位，而人和模型都按数字读文件名——顺序不一致时从第 10 张起整批错位。
2. **同源**：提示里的文件名清单、实际发给模型的图片、写回 `variant_image_map` 的三处顺序
   取自同一份自然序列表；颜色那一趟只发未命名 SKU 图，不掺入商品上已有的映射。
3. **可核对**：提示按附图顺序逐张列出 `#N 文件名`，且只列真正读进来的图（坏图被跳过时编号不会错位）。
4. **写法一致**：颜色列表与映射键使用同一套归一化（`normalize_color_label`），
   匹配时忽略大小写与空格，避免 `Light Purple` / `LightPurple` 对不上导致映射被丢掉。

### 固定色板（2026-09-21 补）

视觉模型命名颜色时只能落在这 9 个固定颜色上：`Apricot`、`Purple`、`Blue`、`Red`、
`Black`、`White`、`Pink`、`Brown`、`Green`（操作员指定，是店铺颜色轴的取值集合）。

- 提示词直接给出色板，要求模型选最接近的一个，不许自造复合名（`LightPurple`、
  `Cream White`）或中文回答；颜色那一趟（`color_only`）的 user 提示再复述一次，
  标题/详情那一趟不带色板，免得标题被拽去写颜色。
- 返回结果按色板再归一化一次（`vision_listing.snap_color_to_palette`）：整串命中 →
  去掉深浅前缀再认（`darkgreen` → `Green`、`light blue` → `Blue`）→ 逐词认并取
  最靠后的命中词（`cream white` → `White`、`sky blue` → `Blue`）；近似色走同义词表
  （`navy` → `Blue`、`lavender` → `Purple`、`maroon` → `Red`）。
- 色板里没有的颜色（灰/黄/橙/卡其/青）和套装标签（`Costume`/`Wig`/`Costume + Wig`）
  保持模型原话：宁可在界面上让操作员看到再手改，也不悄悄换成另一个颜色。
- 文件名扫描器（中英词表）是确定性映射，不受这条限制。

裸数字键的匹配优先级：整文件名 → 主干 → 该文件独有的数字段 → 提示编号 `#N`；
多个文件共用的数字段（`1 (3).png` 里前导的 `1`）不得当作匹配键。

「重试 AI 识别」以这一次识别为准：未命名文件上残留的旧绑定不带进来，重试要能修好既有错配。

## 错误处理

- 文件名为空、只有 `SKU-` 前缀或没有有效颜色段时，不生成颜色候选，继续使用现有回退逻辑。
- AI 不可用时保留文件名解析出的颜色候选，不阻断导入。

## 测试要求

- 覆盖 `主图-`、`Main-`、大小写混合前缀。
- 覆盖 `SKU-红色-01`、`SKU-奶油白`、英文颜色和无颜色段输入。
- 覆盖中文颜色名映射（`杏色`/`棕色`/`深蓝色`/`浅蓝色`）以及自造色名（`奶油白`/`米白`）保持原样。
- 验证主图进入产品图、SKU 颜色进入变体图和颜色列表，并保持去重与稳定顺序。
- 覆盖固定色板：色板名/近似色/复合写法的归一化，套装标签与色板外颜色原样保留，
  以及颜色那一趟提示词里确实带着色板、标题那一趟不带。
