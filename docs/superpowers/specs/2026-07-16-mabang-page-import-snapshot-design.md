# 马帮当前页采集快照重构设计

## 目标

将“从马帮当前页导入”重构为可检查、可确认、可追溯的三阶段流程：

1. 只读采集马帮当前商品编辑页，生成独立快照。
2. 在系统中预览采集覆盖范围、缺失项和冲突。
3. 操作员确认后，才更新店铺目录、类目规则、活动目录和店铺模板。

采集不得保存或发布马帮页面，不得伪造店铺、类目、活动或交易信息编号。

## 当前问题

现有实现将页面采集、类目规则和模板写入放在一次 `/collect` 请求中，造成以下问题：

- 店铺 ID 写进模板，但没有注册到店铺选项目录，模板表单店铺下拉为空。
- 尺码仅保存在变体摘要中，没有写入模板 `sizes`，复选框未勾选。
- 通用 DOM 扫描把“尺码图表”和“变种属性”误当成平台分类属性。
- 类目规则字段与模板已选值混用，未选属性和错误字段污染版本。
- SKU 折扣百分比被误认为店铺活动，但没有真实活动 ID。
- 空重量和空包裹尺寸曾被数值转换为 `0`。
- 每次失败尝试仍可能生成新的模板版本和类目规则版本。

## 方案选择

### 推荐：采集快照、预览、确认写入

采集器只负责生成结构化快照。服务端先验证快照并保存为 `collected` 状态，前端展示预览；确认接口再以一个原子事务写入业务数据。

优点是数据来源、缺失项和写入结果清晰，错误采集不会继续污染模板。代价是导入流程增加一次确认操作。

### 不采用：继续逐字段修补直接写入

改动较少，但采集器与模板模型继续耦合，任何新页面结构都会直接污染业务数据。

### 不采用：完全重新调用马帮接口

接口数据较完整，但马帮前端使用内部认证和请求封装，接口稳定性及授权边界不可控。可作为特定字段的只读补充，不作为唯一数据源。

## 采集数据源

按以下优先级读取，任何来源都只能执行只读操作：

1. 马帮详情页已有 Vue 组件状态。
   - `$refs.storeCategory`：店铺、类目、平台属性及当前选中值。
   - `$refs.variantAttribute` 和 SKU 表格：颜色、尺码、SKU、库存、重量、包裹尺寸。
   - 交易信息组件：当前活动和活动候选项。
2. 当前页面已加载资源 URL，仅用于校验真实店铺 ID、类目 ID 和来源接口。
3. 可见 DOM 文本，仅作为名称和路径的回退来源，不生成内部 ID。

禁止通过全页面通用必填 DOM 扫描生成平台分类属性。

## 快照契约

`MabangImportSnapshot` 包含：

- `store`：真实店铺 ID、中文名称、平台、站点。
- `category`：真实叶子类目 ID、完整路径、类目 ID 路径。
- `selected_attributes`：仅包含当前页面已经选择且值非空的平台属性。
- `missing_required_attributes`：马帮标记为必填但当前未选择的属性，仅用于提示和阻止自动化，不写入模板属性值。
- `variation`：颜色、尺码及 SKU 数量，尺码从全部 SKU 行去重。
- `transaction_defaults`：库存、重量、包裹长宽高及一致性状态。
- `promotion_catalog`：当前店铺可读取到的完整活动目录。
- `selected_promotion_id`：页面当前选择的真实活动 ID；没有 ID 时为空。
- `coverage`：每个分组的 `complete`、`missing` 或 `conflict` 状态。
- `provenance`：字段来源类型，不保存马帮 token、cKey、cookie 或完整敏感 URL。

快照不得包含“尺码图表”“变种属性”等非平台分类属性。

## 字段规则

### 店铺

店铺 ID 和名称都必须存在。确认导入时同时 upsert 到 `mabang_store_options`，然后写入模板。前端确认成功后重新加载店铺选项，并选择该店铺。

### 分类属性

类目规则元数据和模板值分开保存：

- 规则侧可记录马帮返回的属性 ID、名称、类型、必填标记和选项。
- 模板 `attribute_values` 只保存当前页面非空的已选值。
- 未选择的必填属性只进入 `missing_required_attributes`，不生成空模板字段。
- 预览明确提示缺失必填属性；存在缺失时模板可保存为“不完整”，但不能生成自动化任务。

### 颜色与尺码

- 颜色和尺码从所有 SKU 行去重，保持页面顺序。
- `variation.axes` 保存颜色、尺码轴及其值。
- 尺码同时写入模板 `sizes`，包括 `2XL` 等非标准值；前端动态生成并勾选相应复选框。
- 不从空的变体下拉缓存推导尺码。

### 交易信息

- 库存、重量、包裹长宽高从所有 SKU 行读取。
- 所有 SKU 值相同且非空时，提升为模板统一默认值。
- 值为空时保持空，不转换为 `0`。
- SKU 间不一致时不取第一行，标记 `conflict`，由操作员在预览中选择统一值或稍后补充。

### 店铺促销活动

- 活动必须具有马帮真实活动 ID、可读名称、折扣和状态，才能进入活动目录。
- 当前页面只有折扣百分比或折扣价，没有活动 ID 时，状态为“活动未配置”。
- 不生成假活动 ID，不把 SKU 折扣百分比当成店铺活动。
- 确认导入时只更新当前店铺的活动目录，不影响其他店铺。

## API 流程

### 创建任务

`POST /api/mabang-page-imports`

创建 `pending` 导入任务，只保存平台、站点和冲突处理方式。

### 采集快照

`POST /api/mabang-page-imports/{id}/collect`

只读采集并验证，保存快照，将任务状态改为 `collected`。该接口不得更新店铺模板、类目版本、店铺目录或活动目录。

### 查看快照

`GET /api/mabang-page-imports/{id}`

返回任务、快照、覆盖状态、缺失项和冲突项。

### 确认导入

`POST /api/mabang-page-imports/{id}/confirm`

以一个原子事务完成：

1. upsert 店铺目录；
2. 创建干净的类目规则版本；
3. 更新当前店铺的活动目录；
4. 创建或更新店铺模板；
5. 保存模板版本和导入审计记录。

任一步失败时不得写入部分结果。

## 前端流程

导入弹窗分为两个状态：

1. “采集当前页”：显示连接状态和采集进度。
2. “采集预览”：按店铺类目、已选属性、颜色尺码、交易信息、促销活动分组展示。

每组显示完整、缺失或冲突状态。操作员点击“确认导入”后才写入模板。确认成功后前端重新加载：

- 店铺选项；
- 店铺模板；
- 类目规则；
- 店铺活动目录；

然后打开已更新模板，店铺、尺码、属性和可用活动必须正确回填。

## 错误数据修复

提供一次性、幂等的修复函数，范围限定为本次错误导入产生的数据：

- 目标店铺：`2022625115`（POD菲律宾）。
- 目标类目：`100244`。
- 删除类目规则中的非平台字段“尺码图表:上传图片选择模板”和“变种属性:”。
- 从模板 `attribute_values` 和 `category_attributes` 删除同名污染值。
- 将当前真实已选属性保留为平台属性 ID 键值。
- 从 SKU 快照恢复模板尺码；没有快照时不猜测。
- upsert 店铺目录，使店铺下拉可选择。
- 对由错误采集生成且仅含污染字段的重复类目版本进行删除或失效处理，并让 profile 指向新建的干净版本。
- 旧模板版本仅作为审计历史保留，不作为当前表单数据源。

修复执行前后记录数量和目标 ID；不得修改其他店铺、类目或模板。

## 错误处理

- 找不到详情页：任务保持 `pending`，提示打开具体商品编辑页。
- 店铺或类目真实 ID 缺失：采集失败，不生成快照。
- 部分业务字段缺失：快照状态为 `collected_with_warnings`，允许预览，不自动确认。
- Vue 结构变化：返回具体缺失分组，不回退为伪造值。
- 会话过期：提示重新登录马帮，任务不写入业务数据。
