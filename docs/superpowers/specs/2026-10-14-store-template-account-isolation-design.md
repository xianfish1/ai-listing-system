# 店铺模板按马帮账号隔离设计

## 目标

店铺模板归属于某一个马帮账号：模板列表、编辑器里的店铺下拉、以及「复制到店铺模板」选择器都只呈现当前账号的模板与店铺，避免把 A 账号的店铺配进 B 账号的登录态里。

## 背景

系统早已按账号隔离浏览器登录态（独立 CDP 端口与 Profile）、会话（Worker 槽位）和自动化任务（`account_id`），但模板只记了 `mabang_store_id`：两个账号若有同名店铺或同一个店铺编号，模板无法区分，只能靠操作员自觉。

## 归属规则

模板的 `account_id` 按以下顺序确定（服务端唯一入口 `_resolve_store_template_account`）：

1. 显式传入的 `account_id`（前端按当前账号带上来），并校验该账号确实拥有这个店铺；不属于则报错「该店铺属于其它马帮账号」。
2. 所选店铺在店铺目录里唯一命中一个账号 → 用该账号。
3. 店铺在多个账号下都存在 → 报错要求先指定账号，绝不猜。
4. 店铺还没采集过、或老模板没有账号 → 沿用原账号；否则落默认账号（第一个启用账号）。

换店铺保存时账号跟着新店铺走（`update_store_template` 会先丢掉继承来的旧账号）；「另存为模板」换店铺后跟随目标店铺账号；同店「复制」跟随源模板账号。

## 历史数据回填

启动加载时按上述规则给没有 `account_id` 的非归档模板补写账号：店铺唯一命中即写该账号，命不中写默认账号；归档模板不动。回填幂等，且在没有账号实体（单账号时代）的库上不动作。

## 页面行为

- 店铺模板页顶部新增「马帮账号」下拉：默认选中默认账号；未配置多账号时禁用并显示「默认账号（未配置多账号）」。
- 切换账号后重新拉取该账号的模板并重画模板卡片与店铺下拉，「复制到店铺模板」的勾选集合清空。
- 模板卡片标注归属账号名（未配置多账号时不显示）。
- 模板编辑器里的店铺、CNSC 店铺、目标站点店铺、「另存为模板」目标店铺都只列当前账号的店铺。
- 打开一个属于其它账号的模板（例如刚导入的）时，页面先切到该模板的账号再打开编辑器。
- 刊登副本列表回显模板信息时用全量模板索引，不受当前账号过滤影响。

## 接口

`GET /api/store-templates?account_id=<id>` 只返回该账号的模板；不带参数保持旧行为（返回全部）。创建、更新、导入、复制、同店复制都会写入或校正 `account_id`。

## 非目标

- 不隔离基础商品、素材库、刊登副本与自动化任务（它们已有自己按账号/店铺的归属链路）。
- 不提供「全部账号」聚合视图，也不做模板跨账号搬家按钮（换店另存即可跨账号）。
- 不改动描述模板（description profile）的店铺绑定：它仍是全店通用的配置。

## 验收标准

- 两个账号各有同名店铺时，模板列表与店铺下拉互不可见。
- 带错账号创建模板被拒绝，中文报错可读。
- 现有 5 个模板（3 个在用）启动后自动带上正确账号，归档模板保持不动。
- 复制到店铺模板的选择器只列当前账号的模板。
- 新增 pytest 覆盖归属推导、列表过滤、跨账号防护与回填，原有用例不回归。
