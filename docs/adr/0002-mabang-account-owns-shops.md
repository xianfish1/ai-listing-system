# 马帮多账号一视同仁，账号只挂在店铺上

马帮有多个账号，每个账号各自拥有一批互不重叠的店铺（账号 1 : N 店铺）。账号之间没有系统需要
维护的层级关系：主账号登录后能看到子账号的店铺，这是马帮自身的权限表现，系统不为它建模，也不
区分主/子角色。所有账号结构相同——各自一份凭据、一个 CDP 端口、一个 Chrome Profile、一批自己
采集到的店铺、一条自己的自动化队列。

因此店铺与任务只需要一个 `account_id`：「归属账号」恒等于「采集/执行时的会话账号」。唯一键是
`(account_id, platform, mabang_store_id)`，这同时修掉现有 `(platform, mabang_store_id)`
去重键在第二个账号采集时互相覆盖、以及合成 ID `cnsc-store-1` 必然碰撞的缺陷。同一个店铺 id 出现
在多个账号下时只提示、不自动合并，由操作员决定它属于谁。

账号仍然只挂在店铺上，不挂在店铺模板上。模板 → 店铺 → 账号 的推导关系成立，但把账号写进模板是
归属层错位：账号 : 店铺 : 模板 = 1 : N : M，账号会重复写在每个模板上，换绑要改所有模板，同一
店铺的不同模板还可能写出互相矛盾的账号；跨境副本用 `target_site_stores` 表达一个副本跨多站点，
账号绑死在模板上会和多店模型冲突。

本条扩展 ADR 0001：复用现有 CDP 会话的结论不变，只是从「一个会话」变成「每账号一个会话」；
「一个 Chrome Profile 首期只运行一个保存 Worker」的约束按账号各保持一份。
