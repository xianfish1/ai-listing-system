# 同一马帮账号多槽位并行：一个账号可以有 N 只采集浏览器

现场：13 个 Shopee 店铺全挂在同一个马帮账号 `13714205569` 下。ADR 0002 定下「账号 : 店铺 = 1 : N」，
而 ADR 0001 定下「一个 Chrome Profile 只运行一个保存 Worker」，两条合起来的后果是：**同一个账号的
店铺只能排队上架**——一个账号一只浏览器、一个 Worker，一次一单。多账号并行救不了它，因为瓶颈不是
账号数量，而是账号内部的并发度。

因此引入「槽位」（slot）：`slot 0` 是账号自己的那只浏览器（老行为，端口 = 账号端口、Profile = 账号
Profile）；`slot k>0` 是同一账号的额外一只浏览器，端口 = `账号端口 + k*100`，Profile = `<账号 Profile>-slot{k+1}`。
每个槽位一个 Worker 进程、一份 runtime 目录（状态/锁/日志）、一份 `pending-completion` 文件。

## 决策

1. **槽位是「同一账号的独立浏览器」，不是「同一只浏览器开多标签」。** 一只浏览器共享登录态与页面，
   而 Worker 的启动清理、掉线恢复、页面导入让路都假设自己独占它（2026-10-05 现场：9223 被两个
   使用者反复杀/起，把操作员的导入窗口收走）。槽位靠端口 + Profile 双隔离，互不干扰。
2. **槽位数是全局设置**（`worker.slots_per_account`，1~4，默认 1），对所有启用账号生效；**但只有
   名下有店铺的账号才会拿到额外槽位**——没店铺的账号不产生上架任务，为它多开浏览器纯属浪费内存与
   登录会话。店铺目录读不出来时 fail-open（按有店铺处理），不让一次读取抖动把并行度悄悄降回 1。
3. **槽位数改动立即生效**：调大 → 给新槽位开浏览器并自动登录、启动它们的 Worker；调小 → 停掉多余
   Worker 并关掉它们那只浏览器。不需要重启 API（1 号槽位的 Worker 命令完全没变）。
4. **不锁店铺**：槽位只按账号隔离，同一账号任意单都可以并行（操作员选的口径），并发粒度不做到
   「同店铺串行」。
5. **登录态各自独立**：新槽位是全新 Profile，没有 cookie，必须重新自动登录一次；凭据取账号里已存的
   加密密码。同一马帮账号多会话是否被平台限制，属于要真机验证的风险，因此首期只开 2 槽、只保存草稿。

## 未被推翻的部分

- 页面导入（`从马帮当前页导入`）仍然只发生在 1 号槽位的可见窗口上；它只让 1 号槽位的 Worker 让路
  （导入记录带 `slot`），2 号槽位的 Worker 各用各的浏览器，不必停。
- 账号之间仍然完全隔离（ADR 0002）；槽位只是把「隔离」从账号层延伸到账号内。
- 马帮保存闸门不变：只保存草稿，永不点发布。
