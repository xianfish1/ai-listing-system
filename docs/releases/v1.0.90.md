# v1.0.90

本版修复**商品标题超长导致整单填写失败**的现场问题：马帮「商品标题」输入框只接受 100 字符，标题 101–120 字符时页面会静默截断，执行器回读与期望值不一致，任务在 `fill_basic_info` 阶段报 `field_value_not_verified` 并 blocked。

## 修复

- 填写前读取控件自身的 `maxLength`，商品标题超长时按**词边界**裁剪后再填入，避免页面截断造成回读失败。
- `fill()` 之后改为最多轮询回读 2.5 秒，兼容 Element UI 的异步回写；原来只读一次，页面重渲染时可能读到旧值/空值。
- 页面仍按自己的上限截断时（`maxLength` 属性读不到但 JS 里 slice），标题字段按页面实际能存下的值放行，不再为几个字符把整单卡成 blocked。
- 不匹配时把 `expected / actual / max_length / tag / readonly / disabled` 写入 `tmp_upload/auto-fill-debug.log`，下次现场问题可直接定位。
- 描述等长文本不启用自动裁剪：仍严格回读，避免把被截断的描述当成保存成功。

## 验证

- 现场任务 `fa07fdc5-f2e1-4e5f-830f-8ff2c193c46c`（Oct.1N / AL1622）：标题 103 字符，修复前 `field_value_not_verified`；修复后按 100 字符上限裁成 96 字符，`fill_basic_info` 通过，整单保存成功（保存草稿，未刊登）。
- 新增回归测试：`tests/mabang_playwright_executor.test.cjs`；`node --test` 共 162 项全部通过。

## 升级提示

- 无新增依赖；不改数据结构、不改 `data/`、`storage/` 和 `.env`。
- 行为变化：标题超过马帮输入框上限时，会按平台实际上限截短保存；完整标题仍保留在店铺刊登副本里，需要完整展示时请把副本标题改到 100 字符以内。
