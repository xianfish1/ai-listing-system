# v1.0.80

本版包含两块新内容（**从 Excel 导入基础商品**、**CNSC 3PF 执行器提速与填全**），并**补回 v1.0.79 里丢失的三处修复**（页面导入取消、CDP 端口自愈/迁移、CDP 默认端口 18223）。

## 补回：v1.0.79 丢失的修复

- **页面导入取消**：关闭「从马帮当前页导入」弹窗会调 `POST /api/mabang-page-imports/<id>/cancel`；同一账号同一槽位开新导入会就地把旧的置为 cancelled；API 启动时清理上一次进程遗留的「进行中」导入。少了这三处，弹窗关掉后 run 仍算进行中，Worker 会一直「等待页面导入」，自动化任务全部待领取（最长 30 分钟）。
- **CDP 端口自愈与老库迁移**：端口被别的 Chrome 占着且命令行匹配不到本账号 profile 时，按端口找到占用者（只杀 `chrome.exe`）再等端口释放，报错带 `PID/进程名`；老库账号端口 / `worker.cdp_url` 仍是 9223 的，读写库时自动迁到 18223（幂等，不会二次漂移）。
- **CDP 默认端口回 18223**：执行器 `CDP_DEFAULT` 与前端回退端口都回到 18223，避免默认去抢最容易被占用的 9223。

## 新增：从 Excel 导入商品

- 基础商品页新增「从 Excel 导入」按钮，读马帮「导出在线商品」的 `.xlsx`：一行一个子 SKU，按 `Parent SKU + product id` 聚合成一条 listing，先预览（主 SKU、标题、颜色、尺寸、图片数、源店铺、状态）再勾选开始。
- **只建基础商品**：标题、商品图/变种图、颜色来自 Excel；价格、描述、分类属性、尺码、尺码表继续由店铺模板提供，不写进商品（避免纯净跨境场景下顶掉模板尺码）。
- 颜色名基本原样保留；只有 `PureWhite` / `Pure WHite` 这类 `Pure*` 别名并入基色 `White`。变种图与商品图 URL 或字节相同（马帮导出里很常见）时直接复用同一张商品图，不再复制第二份。
- 图片下载到 `storage/uploads/excel-imports/<批次>/<主SKU>/`，素材 `origin="excel_import"`；进度每商品落盘，API 中途重启会显示 `interrupted` 并可重试，已下载文件复用。
- 主 SKU 已存在的直接跳过（预览阶段就标记，不下载图片）；同一父 SKU 多店铺多条 listing 分条导入，后一条主 SKU 加 `-2` 后缀。
- 导入完成后列表自动刷新（商品 + 素材一起），如果当前筛选把新商品挡住会清回默认并把第一张新卡片滚进视野。
- 批量删除预览批次：`DELETE /api/excel-import/batches/<id>`（批次里的商品已导入成功时会拒删，图片仍被商品引用）。

## 改进：店铺模板「类目」跨站点保留

- 另存模板到别的站点时不再清空平台类目：类目 path/id 是平台级（8 个站点实测同一个 `Men Clothes > Tops > T-Shirts` 都是 `100244`），跨站点只清空跟站点绑定的类目方案、必填属性与价格，到目标店铺采集当前页时会重新绑定方案。
- 切换店铺时保留已选类目；「已选类目但还没有该类目规则」的提示改成中文可操作说明（去「采集必填项」或改选已采集的类目）。
- 店铺尺码图模板选择在切换店铺、重新打开模板时不再被清空，保存时写入模板 id；「类目与活动」说明文字改为与实际行为一致。

## 改进：Worker 每次启动重读设置

- 多账号 Worker Supervisor 是常驻对象，之前闭包捕获了旧的 worker 配置：把 `lease_seconds` 从 120 改成 300 再点重启，新进程命令行还是 120（执行器超时仍按旧 lease 算）。现在每次起进程都重新读设置，改完点重启即生效。

## 修复：3PF 保存被静默拒绝（`save_result_not_proven`）

- 现象：保存按钮点下去了，但没有成功弹窗、没有 save 响应，任务停在 `needs_confirmation`。
- 原因：3PF 页面的「交易信息」用**单一必填列「库存」**代替全球页面的泰国/广州/菲律宾三仓库存列，执行器只写价格和三仓库存，70 行 SKU 的库存全部留空，马帮因此拒绝保存且不弹任何提示。
- 现在：新增 `stock` 列定义（仅 3PF 启用，页面没有该列时跳过），值取 `sku.stock`，缺失时退回三仓之和；写入后逐行回读校验。

## 修复：`Cannot read properties of undefined (reading 'sku')`

- 原因：`validateBeforeSave` 第二次调用 `buildCNSCDomGridPlan` 时漏传 `warehousesRequired`，3PF 没有三仓列 → 返回 `ok:false`（无 `columns`）→ 下一行读 `plan.columns.sku` 抛错，整单失败且没有阶段信息。
- 现在：两处调用使用同一套 options，`plan.ok` 为假时不再读 `columns`；同时给 VXE 表格的空行加了过滤（虚拟滚动会短暂出现 undefined 行）。

## 修复：分类属性大量漏填

- 原因：马帮默认只渲染必填属性，其余折在「显示所有属性」后面；展开逻辑原来只对本土（site）生效，3PF 的 15+ 个可选属性（原产地/图案/季节/风格/领口/推荐年龄…）被当成「页面没有该属性」静默跳过。
- 现在：3PF 进入逐字段填写前先展开「显示所有属性」（选择器对 3PF 放宽，取最内层可见元素），逐字段兜底也支持；日志新增 `attributes_expanded` / `attributes_expand_failed`，可直接看到展开前后的表单项数量。

## 修复：`select_option_not_unique` 与「页面上该字段不唯一」

- 选项歧义：页面渲染的是中英双语标签（如 `棉花 (Cotton)`），按英文 `Cotton` 搜索会同时命中 `精梳棉 (Combed Cotton)`。现在按**结构化变体**收窄——候选的某个变体与搜索词完全相等才算点名命中；收窄失败才判歧义（仅 3PF）。
- 字段歧义：`尺寸` 的子串匹配会撞上物流的「包裹尺寸」（长/宽/高三个输入框）。3PF 改为按标签前缀锚定，锚不到才退回原逻辑。

## 性能：3PF 整单从约 9 分钟降到约 5 分钟量级

| 优化点 | 改前 | 改后 |
| --- | --- | --- |
| 表单项定位（`formItemByOwnLabel`） | 逐项 3 次往返，单次扫描 0.5~3 s | 一次 `evaluate` 算完，几十毫秒 |
| 每个属性扫描次数 | 3 次（找字段 / 落值 / 回读） | 1 次（复用已解析的表单项） |
| 选完选项的稳定性回读 | 每 100 ms 重扫整表 + 昂贵的选项定位器（单次迭代可达 60 s） | 直接复用表单项，仅在文本未命中时才读选项行 |
| `validate_before_save` 审计 | 546 s（对 `body *` 每个节点做样式与布局计算） | 3 s（先用 textContent 廉价预筛，最终判定仍是可见性 + innerText） |

## 稳定性

- **可选属性**填写失败不再阻断整单：记 `skipped_optional_failed` 并降级为 warning，草稿照存、任务落 `saved_with_warnings`；必填属性仍然阻断。
- 执行器超时预算与 lease 对齐（`max(300, lease×4)`），Worker 每次启动重读设置，改完 lease 重启即可生效。
- 尺码图 URL 的私有地址校验抽到 `services.api.url_guard`，Excel 导入与尺码图导入共用同一套规则。

## 升级后

- 重启程序即可，不需要清理任务或数据。
- 从 v1.0.79 升级的机器：之前卡在「等待页面导入 / 待领取」的任务会在 API 重启后恢复领取；老库 9223 端口会自动迁到 18223。
- 如果之前的任务是在旧版本跑失败/阻塞的，点「再次尝试」会重新走新逻辑（同一条任务记录，不会产生重复刊登）。
- 建议观察一条 3PF 任务跑通：页面「交易信息」应显示已完成，任务状态为 `saved_with_warnings`，详情里能看到跳过的可选字段。
- Excel 导入先拿一个小批次试跑：预览里颜色数、图片数与源 listing 对得上，再全选导入。
