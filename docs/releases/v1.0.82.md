# v1.0.82

本版修三件事：**型号「自选值」一直填不进去**、**物流信息卡撞名导致整单 blocked**、**类目方案（分类属性）不分本土/跨境**。

## 修复：型号(101639) 的「＋ 添加自选值」填不进去

- 现场：马帮「型号」下拉里没有任何枚举，只有一条「＋ 添加自选值」。自动化跑完，草稿里型号仍为空。
- 根因：执行器只认文案**恰好是「添加」**的按钮/链接，而且要求下拉面板里有可见输入框；现网入口是「＋ 添加自选值」，且这个下拉不可搜索（面板里没有输入框）→ 流程在「找入口」阶段就返回，`tmp_upload/auto-fill-debug.log` 里全是 `custom_option_add_missed`（`before=[]`、`echo=""`）。
- 修法（`scripts/mabang_playwright_executor.cjs`）：
  - 认「添加自选值 / 添加自填选项 / 添加自定义值 / 旧版『添加』」四种入口，优先带「自选/自填」的那条；整段容器文本不算，避免点到容器。
  - 先点自选入口 → 等**点击后新增**的输入行（兼容面板原本 0 个输入框）→ 逐字键入（含 contenteditable）→ ✔ / 确定 / 回车确认。
  - 老 UI 的「搜索框 + 添加」两步流程保留，原产地那类自选值不受影响。
  - 新增诊断阶段 `custom_add_entry`（入口文案 / inputs_before / row_found）与 `custom_add_entry_missing`。
- 验收：node 161 项全绿；用仿 Element UI 的两页 DOM（新入口 / 老入口）驱动执行器真函数，新代码 `{value:"T-shirt", method:"custom_option_ui"}` 且标签真的进控件；同一 fixture 跑改动前的代码是 `custom_option_add_failed`。

## 修复：物流信息卡撞名（`logistics_card_not_unique`）

- 现场：HN_POD 一批 7 单全部 `fill_logistics_info` blocked，`details.count=2`。
- 根因：交易信息卡的卡头新挂了「商品级预购（物流信息）」角标、卡里还有「未勾选时，预购仍在物流信息里设置」提示，用整卡文本匹配「物流信息」会同时命中两张卡。
- 修法：按卡头（`:scope > .el-card__header`）精确认卡，卡头读不到才降级为「含物流信息且不含交易信息」；重量/包裹尺寸改成按自身 label 精确匹配（防「重量」撞「重量限制」）。失败时把 `headers` 一起报出来。
- 验收：7 单原地重跑全部 `fill_logistics_info ok` → saved。

## 变更：类目方案（分类属性）按「本土站点 / 跨境站点」分作用域

- 本土 `site` → 店铺国家方案（`shopee-ph-*`）；跨境页 `cnsc_global` / `cnsc_3pf` → **GLOBAL** 方案（`shopee-global-*`）。同一类目在两侧是两份必填项规则。
- 页面采集：CNSC 页一律采集到 GLOBAL 方案——**此前 CNSC 页按店铺国家采集，会把本土方案顶成跨境属性集**（现场：101773 的本土 15 字段曾被覆盖成跨境 40 字段）。3PF 模板自身 `country` 仍保留店铺国家（描述配图上限按站点算）。
- 模板校验：跨境模板的方案必须是 GLOBAL（老数据绑店铺国家方案仍放行）；本土模板不接受 GLOBAL 方案。
- 前端：编辑器类目区显示「类目方案：本土站点（PH）/ 跨境站点（GLOBAL）」；切换刊登模式自动重绑；同一作用域优先选有字段的方案（避免空方案把属性清空）；保存时显式带上 `country`。
- 存量：广州小苗 CNSC 模板仍绑 `shopee-ph-100226`，可以继续用；在 CNSC 页对该类目做一次「采集当前页」会生成 `shopee-global-*` 并自动切过去。
